# Bounded Monitor context and model adapter

This is a Loopia-local composition addition, not a claim that the full canonical PromptOps execution platform is ported. It consumes the explicitly reconciled product prompt pack and preserves the pinned M01/M02/M03/M04/M05/M06 authority chain. Native model execution remains inactive: the provider component has no active application construction, its constructor defaults to inactive, and the current prompt records are `DRAFT`/`INACTIVE`. If the separately composed workflow factory is present, the foundation check permits only its exact `OpenAIResponsesTransport(false)` construction. Passing `true` to the transport cannot activate an inactive prompt. Offline fixtures prove contracts and composition, not model quality or real provider success.

## Context and immutable preparation

`Workflow\ContextEnvelope::prepare($scope, $selection)` requires current `evidence.read` authority, an active same-scope M04 mission, and explicit source selection contained in that mission's `allowed_source_scope_ids`. The mission objective becomes the purpose; the caller cannot replace it. Internal audience, input bytes, output tokens, model-attempt count and maximum observation age are explicit bounded inputs. `selected_target_org_role` must resolve to an existing same-scope P04 target. The exact target and redaction profile enter `envelope.routing_target` and its digest; a generic audience never implies an organizational role or membership. A changed target policy invalidates prepared context.

The owner profile is an M05 uploaded capture whose private `EvidenceStore` bytes must still match their content address. It is labelled `TENANT_PROVIDED`, never independently verified, and does not create or promote a company twin. Observations must be actual P01 snapshots with matching M05 and successful M06/M01 host-capture lineage. Supplied in-memory URL/body bytes must match the exact canonical URL/body digest of both evidence and snapshot. A caller cannot supply prose on the strength of a citation alone. The envelope records original timestamps, evidence IDs, source IDs, snapshot sequence, content digests and current source-policy digest. Selected source and evidence lifecycle state are re-evaluated.

This first body-retention path requires `standard` retention, `standard_cache` or `explicit_contract`, derived-summary permission, current approved policy, and URL scope. `no_cache`, short, minimized and prohibited retention are refused. Existing P01 line fingerprints are never reconstructed into text. Private workflow artifact retention is the composing runner's responsibility; it must validate the current context before persisting permitted source bytes. Profile and body are not written to model telemetry.

One observation may prepare a baseline context. A classifier request requires exactly two ordered snapshots from one monitored source. A battlecard request requires a digest-bound classifier candidate; critic requires the corresponding battlecard candidate. The earlier output is a separate untrusted input. Its schema and citation membership are checked again, while the workflow journal proves its persisted origin. It is never appended as instructions. Extra request options, caller instructions, provider tools, arbitrary endpoint/model selection and cross-context predecessors are refused.

The separate fourth role, `MONITOR_ROUTING_CRITIC`, additionally requires `ContextEnvelope::routingPackage($context, $roleDistributionBriefingId)`. The server-produced envelope/digest contains the exact pending P04 summary, target, same-mission released P01 identity/decision and frozen/current redaction profiles. Before and after dispatch, the executor re-reads it, checks current M10 reliance/configured policy and compares the prior draft's five P01 content fields to the actual released battlecard. The earlier battlecard critic is never reused as a routing sensitivity judgment. No routing verdict or distribution is granted by this model response.

`ModelRequestBuilder::prepare($resolvedPrompt, $context, $options)` returns an immutable `PreparedModelRequest`. It compares the whole prompt record to a fresh packaged resolution, not just caller-supplied hashes. `inspect()` exposes the exact body, provenance and request digest for private operator review; this contains source/profile text and must not be sent to an unscoped public log or response. Mutating inspected values cannot alter the serialized request.

## Dispatch, setup and credential authority

`ModelRegistration::ensure($scope)` requires existing `runtime_host_binding.administer` authority and creates or validates exact global descriptors: tool `monitor.model.v1`, operation `monitor.model.infer`, host/adapter `loopia-monitor-model-v1`, `INTERNAL_TRANSFORM`/`ANALYZE`. It never grants roles, tool rights, a mission assignment, credentials, model activation or release authority. Conflicting existing definitions fail closed. The owner-authorized setup workflow must separately assign explicit M03/M04 rights; a critic uses a separately assigned agent identity.

`CredentialStore::save/revoke` are private internal operator services requiring `tenant.administer` in the selected workspace. There is no provider-credential HTTP route. Save seals the key using existing AES-256-GCM `SecretBox`, binds it to tenant and provider, serializes rotation per tenant and returns only identity/fingerprint. The master key remains private configuration. A dispatch callback opens only an active same-tenant credential after M06/M01 admission. Plaintext exists only in process memory, with best-effort local cleanup; PHP memory copying is not claimed to provide secure zeroization of every copy.

`ModelExecutor::execute($command, $request, $credentialId)` requires the context's original actor and exact tenant/workspace/mission scope. Dispatch passes through all existing M06 gates and M01 nominal admission/single-use claim. M01 additionally verifies the exact model descriptor and persisted request digest. The provider callback is reached only after admission. Current context/policy is revalidated before the call and again before returning a candidate; M01 rechecks authority after the callback. A valid model response is still an untrusted candidate requiring human review and never becomes captured source evidence.

The product Monitor's lifetime mission budget serializes reservations under the mission row. Every admitted **product** reserved attempt consumes one slot, including missing-credential and terminal provider refusals; it does not reset for a new run or retry. P02 synthetic `MODEL_EVALUATION` attempts are separately identified in `provider_attempt_purposes`, spend the evaluation grant's budget, and are excluded from that product-mission count even when the same M04 mission/assignments carry M06 authority. Historical attempts with no purpose row retain product-budget semantics. Recurring monitoring requires explicit new bounded mission/grant decisions. M06 idempotency returns `MODEL_REPLAY` without re-running the provider. A normal read-only run replay displays candidate artifacts already recorded by a completed stage. An interrupted dispatch returning `MODEL_REPLAY` is instead blocked as `MONITOR_MODEL_REQUIRES_RECONCILIATION`; the runner does not automatically retrieve a result or resume the stage. A lost response is not an invitation to retry automatically.

## Exact native API contract

The only native endpoint is `POST https://api.openai.com/v1/responses`. Header names are `Authorization` (Bearer credential), `Content-Type` (`application/json`) and `Accept` (`application/json`). Request fields are `model: gpt-4.1-nano`, packaged `instructions`, canonical serialized context as `input`, bounded `max_output_tokens` (16–2048), `store: false`, and `text.format` with `type: json_schema`, `name: monitor_candidate_v1`, `strict: true` and the exact packaged output schema. There are no provider tools, redirects, URL overrides or retries. TLS verification stays enabled; transport accepts HTTPS only, disables environment proxy use, bounds response bytes to 131072, and uses 5-second connection/20-second overall timeouts.

The pure parser requires a completed response containing exactly one output-text object, then strict schema validation and PromptOps citation/reference checks. It does not prove semantic entailment. Refusal, incomplete output, invalid JSON/schema, unknown output/tool items and size failures are terminal. Authentication, rate-limit, quota/billing, timeout and unknown network outcomes remain distinct fixed codes. Billing quota codes include `insufficient_quota`, `credit_balance_exhausted`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded` and `organization_usage_limit_exceeded`; the documented `insufficient_quota` type remains a fallback. Raw provider messages, response bodies and credentials never enter error receipts or telemetry.

Migration 190 records append-only attempt identities (request/context/prompt/schema digests, governed tool request, fixture/live mode) and terminal result identities (candidate digest, provider call pointer, sanitized request ID or fixed failure code). Existing `provider_call_records` holds bounded token/latency metadata. Join it to `provider_model_attempts` to distinguish fixture from live execution; a standalone generic provider row is not real-call evidence. Exact source/request/candidate bytes remain in the private workflow artifact bundle. No provider call in the focused tests is live.

## Focused verification

`tests/unit/bounded_model.php` covers immutable exact preparation, closed options/models/schemas, baseline/pair refusal, native inactivity, error sanitization/classification and predecessor binding. `tests/integration/bounded_model.php` uses real MariaDB plus fixture transports through P01/M05/M06/M01 to exercise policy revocation, stale evidence, sealing, scoped authority, replay, append-only provenance, quota, post-callback authority change and budget exhaustion. `tests/integration/bounded_model_stages.php` composes classifier/draft/critic with a separately assigned critic, then tests the separate routing critic against an independently produced real service-fixture release. That fixture is explicitly not a claim that the model draft received human approval. `tests/support/MonitorModelFixture.php` exposes setup and manually authored response fixtures; it grants no release and makes no network call.

## Admission, model policy and evaluation (completion plan P01/P02)

The fixed model, endpoint, byte and token ceilings and timeouts are one closed policy,
`app/Provider/ModelPolicy.php`, with one digest that approvals and grants bind. A live transport
now runs only with `ExecutionAdmission` and a request whose prompt was selected under an admitted
grant; admission is re-checked before reservation, before dispatch and after return, and grant
budget is spent in the attempt's transaction. The single provider-transport constructor is
`MonitorFactory::modelTransport()`, activated only by `admittedModelTransport()` for an ADMITTED
grant. The evaluation lane reuses this executor with `EvaluationCaseContext` as its context
authority. `store=false` is requested; provider-side retention is an account setting reviewed
separately and is not established by this field.
