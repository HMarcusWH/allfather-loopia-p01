# V01 post-freeze PHP 8.5 image build defect — candidate repair

**Date:** 30 October 2026. **State:** repair candidate, not a deployed image or V01 PASS.

V01 source-archive and disposable MariaDB tests passed on frozen integration `18457c305f93ccee0875fadbd738d2ae017cff2d`; however the independent [PHP 8.5 image build](https://github.com/HMarcusWH/allfather-loopia-p01/actions/runs/41127564840) **FAILED** compiling the DOM extension. Dockerfile invokes `docker-php-ext-install -j"$(nproc)" pdo_mysql mbstring curl dom`, and PHP 8.5's DOM code tried to include `lexbor/html/parser.h` and `lexbor/encoding/encoding.h`, which were not present in the Bookworm compilation environment.

The official PHP Docker image already provides version-dependent built-in extensions, including DOM/Lexbor in the PHP 8.5 base; `dom` should not be recompiled on Bookworm. Adding `liblexbor-dev` without verifying its availability in Debian Bookworm is not a safe substitution (Debian package index lists `liblexbor-dev` only in newer suites at the audit date). The minimal fix removes only the trailing `dom` from the `docker-php-ext-install` list. **It retains** the earlier explicit build-time `extension_loaded("dom")` and `class_exists("Dom\\HTMLDocument")` fail-closed checks, along with the CR-01 HTML5 unit/security tests, Apache verification and all other PHP/Node staging declarations.

**Verification requirement:** First prove the exact PHP 8.5.12 official base has the built-in DOM/HTMLDocument using a no-network read-only container probe. Build this corrected Dockerfile only in an isolated CI runner, execute its original build-time CR-01 tests and inspect the built runtime with `--network none` and the image entrypoint bypassed. Also require the five existing GitHub code-qualification lanes (foundation, MariaDB 10.6/10.11, package integrity and code qualification), **zero FAIL/SKIP**, and exact GitHub test-merge tree identity.

**Source-freeze impact:** This is a genuine **post-freeze source defect**. Merging its repair onto the isolated integration branch changes the Git SHA/tree, INVALIDATES the old 29/29 source freeze for further V01/V02 qualification, and demands a **new exact-source archive and checksum**, new CI qualification, and a new V01/V02 source evidence baseline. Preserve old receipts as historical evidence, do not overwrite their PASS/FAIL states. Only the isolated integration branch is in scope; `main`, Railway, Loopia, live database, P10 restore, source/model/provider permissions and customer release remain untouched.

**Authority:** No U01–U10 adoption, model execution, source-use permission, staging deployment, credential rotation, live migration, or V01 host PASS is granted by this Dockerfile edit. The verification issue #134 remains open until the corrected frozen image and exact staging or separately permitted QA host identity are independently accepted.
