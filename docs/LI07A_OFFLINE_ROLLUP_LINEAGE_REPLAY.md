## Determinism, conflicts, late inputs and integrity

- Input identity uses `InputSet::freeze()` and its stable sorted `input_digest`. In-window reference membership uses `WindowEngine::verifyWindow()` and `[start_inclusive_utc, end_exclusive_utc)`. UTC/Stockholm DST and TZDB caveats remain pinned to LI-06A. The actual window candidate/digest, profile snapshot digest, measure digest and full selected lineage digest are included in the outer `rollup_digest = Digest::canonicalDigest(manifest)`. An alternative caller row ordering must not change the candidate.
- **No top-K loss:** Every selected reference (max 256 per existing LI-06A contract) is kept. Contrary or explicit conflict refs, high-diagnosticity refs, UNKNOWN polarity, unknown structural magnitude and missing commercial importance are represented explicitly and are **never averaged away**. Equal payload digests describe exact byte groups, not independent corroborating sources or real-world events.
- Incomplete input gets `status=INSUFFICIENT_INPUT` and empty freshness clocks, rather than asserting `NO_CHANGE`. Even `status=OFFLINE_NOT_ADMITTED` means **complete only within the caller-supplied input set**, not complete against the real source owner, schedule/coverage, current permissions or source-rights history.
- The window bounds are normalized and explicitly recorded as one period identity. `Lineage::proposeLateSuccessor` compares equal full period bounds, exact tenant/workspace/P01 competitor/question scope, data class and profile snapshot digest; it requires every predecessor selected ref unchanged plus at least one newly selected ref. Added references result in a NEW digest without overwriting the predecessor. It cannot infer that a reference was *truly late*, only that the caller supplied it later. Old refs removed, rehashed, altered or selectively hidden refuse.
- `RollupEngine::verify` checks structure, bounded values, exact lineage/measure/contradiction/narrative consistency and digest. `Replay::check` is the **derivation** verifier; integrity alone does not authenticate caller data. Recalculating hashes over a fabricated candidate never grants rights, release or persistent lineage.
- A reported unavailable/redacted ref yields `NOT_REPLAYABLE` with a bounded ref-ID list, never a fabricated replay or a recomputed old source body. Caller claims of availability are **unverified**; the pure precursor does not read the owner store to prove availability. Divergence is a candidate M11 finding trigger for a later authorized implementation, not an automatic M11 write or cleanup.
